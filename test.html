04 | 共通機能アーキテクチャ標準：例外処理とライフサイクル
共通機能の呼び出しから事前の変数定義を全廃し、「正常時の1行受取」と「異常時の例外透過」に徹することで、利用側のバグを排除し障害調査を最短化する。
【実装標準】利用者のコード構造
// 1. try外での変数定義(null代入)は禁止
try {
    // 2. 宣言と受取を1行で完結
    ReturnBean result = service.execute();

    // 正常系のみ子Beanを操作
    ChildA a = result.getChildA();

} catch (CommonSystemException e) {
    // 3. 例外(e)をそのままログに渡す
    logger.error("業務エラー", e);
    throw new AppExc("...", e);
}
【設計意図】裏側で機能する3つの自動化
① メモリの無害化（ライフサイクル管理）
事前の変数定義を排除することで、異常発生時に「使われないnull変数」がスタックに滞留しない。不要な子Beanは即座にGC（ガベージコレクション）の対象となり、NullPointerExceptionの芽を構造的に摘み取る。
② ログの自動結合（例外チェーン）
エラーコードでの紐付け（相関ID検索）を廃止。キャッチした例外オブジェクトをログ出力に渡すだけで、利用側の業務コンテキストと、共通機能内部のスタックトレースが1つのログブロックとして自動連結される。
③ 責務の完全な分離（カプセル化）
インスタンスの生成責任と、詳細エラーの出力責任を共通機能側に完全に隠蔽。利用者は「結果を使うこと」と「業務影響を記録すること」のみに専念できる。
対象: アプリケーション開発チーム ／ 前提: 共通機能は独自例外(CommonSystemException)をスローする設計とする
